This project shows how I used **AWS CDK** and **AWS CodePipeline** to create and manage cloud resources using a proper CI/CD pipeline.

The project creates **three AWS resources** using CDK:

1. **Amazon S3 bucket** – for storing files.
2. **AWS Lambda function** – simple Node.js function.
3. **Amazon DynamoDB table** – for storing items with a string `id` key.

---

## 1. Architecture Overview (Very Simple)

At a high level:

- I write my **infrastructure code** in **TypeScript** using **AWS CDK**.
- The CDK code defines:
  - One **S3 bucket**
  - One **Lambda function**
  - One **DynamoDB table**
- I commit and push the code to **GitHub**.
- **AWS CodePipeline** + **AWS CodeBuild** automatically:
  - Pull the code from GitHub
  - Run `cdk synth`
  - Run `cdk deploy`
  - Update the resources in my AWS account

So whenever I change the CDK code and push to GitHub, my AWS resources are automatically updated.

5.4 CI/CD Flow

I change CDK code locally (for example, update Lambda response).

I commit and push to GitHub main branch:

git add .
git commit -m "feat: update Lambda message"
git push origin main

CodePipeline detects the push and starts a new execution.

Source stage pulls latest code from GitHub.

Build stage (CodeBuild) runs buildspec.yml:

Installs CDK

Synthesizes the stack

Deploys the stack using cdk deploy --require-approval never

If build succeeds, the AWS resources are updated automatically.
